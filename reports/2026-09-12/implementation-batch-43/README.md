# الدفعة 43: تشخيص آمن وتقسيم الوحدات الكبيرة

## سجل الأعطال

- يكتب التطبيق أخطاءه غير المتوقعة في `errors.jsonl` داخل مجلد دعم التطبيق.
- الحد الأقصى 256 KiB للملف النشط مع ملف تدوير واحد، ولا يؤثر فشل الكتابة أو القراءة في استمرار التطبيق أو إنشاء تقرير الدعم.
- يحتوي كل سجل على وقت UTC والوحدة والحدث ونوع الخطأ وبصمة stack ومفتاح العملية عند وجوده.
- لا تُحفظ رسالة الاستثناء أو payload أو اسم العميل أو رقم الهاتف أو مسار الملف أو مفتاح العملية الخام.
- يعرض تقرير الدعم عدد السجلات ووقت آخر سجل فقط؛ ولا يرفق الملف تلقائيًا.

## نطاق الالتقاط

- أخطاء Flutter framework والأخطاء غير المعالجة في async.
- فشل bootstrap وفحص النسخ التلقائي غير المتوقع.
- الاستثناءات غير المتوقعة حول المعاملات المحمية بإيصال منع التكرار للعمليات المالية والمنتجات والورديات.

## تقسيم المسؤوليات

- فُصل البيع والشراء ومرتجعا البيع والشراء والمصروفات من ملف حالات الاستخدام الجامع.
- فُصل تدقيق النزاهة إلى المخزون والدفتر، والخطط والتصحيحات، والمستندات، والمراجع، والمساعدات.
- فُصلت واجهات المصادقة، والنسخ والإعدادات، وإجراءات نقطة البيع، ومربعات الحوار حسب كل مسار.
- حافظت الملفات على مكتبات `part` والعقود القائمة لتكون الخطوة تنظيمية منخفضة المخاطر، مع اختبارات انحدار على العمليات والواجهات.

## التحقق

- اجتازت اختبارات سجل التشخيص والخصوصية والتدوير وتقرير الدعم وفشل الحفظ.
- اجتازت اختبارات تدقيق النزاهة والمخزون والمرتجعات والتصحيحات بعد التقسيم.
- نجح `dart analyze lib test/v2`، واجتازت مجموعة Flutter الكاملة **196 اختبارًا**، ونجح بناء Linux Release، وانتهى `git diff --check` بلا أخطاء.

## الحدود

السجل أداة دعم محلية وليس نظام مراقبة عن بعد، ولا يُرسل أي شيء تلقائيًا. لا يغلق ذلك بوابات جهاز Windows أو الطابعة والماسح والنسخ الخارجي وقطع الطاقة وتجربة المستخدم والتوقيع وجهة الدعم.
