# الدفعة 41: قياس وتحسين قاعدة بحجم إنتاجي

## الحمل المقاس

- 10,000 صنف.
- 50,000 فاتورة بيع مترابطة ومتزنة، مع البنود والمدفوعات وحركات المخزون والقيود.
- 23 عملية بيع فعلية عبر حالة الاستخدام أثناء القياس.
- قاعدة SQLite ملفية على Linux، Flutter test JIT، ومعالج AMD Ryzen 5 PRO 2400G و8 معالجات منطقية.

## التحسين

- استبدل تقرير الفترة تحميل كل الفواتير والمرتجعات لمجرد عدها باستعلامات `COUNT` داخل SQLite.
- أضيفت فهارس للفترات وترتيب الفواتير وأسماء الأطراف والأصناف وحالة خطط الأقساط.
- تُنشأ الفهارس مباشرة على مخطط التطبيق الكامل، وتغطي الاختبارات إنشاء قاعدة جديدة وترقية نموذج صالح من المخطط 3 إلى 11. القاعدة الناقصة أو التالفة لا تُعامل كترقية سليمة.
- صار ترتيب إدخال بيانات القياس صريحًا، فلا تتغير سلسلة حركات المخزون مع اختلاف خطة تنفيذ SQLite.

## الحدود المفتوحة

النتيجة تقيس SQLite وطبقة التطبيق بعد إحماء الاستعلامات، ولا تقيس زمن رسم نافذة Flutter. الفواتير الاصطناعية ذات بند واحد ودفع نقدي. يجب إعادة القياس على جهاز التسليم المعلن وبنسخة Release وبيانات محل ممثلة قبل اعتماد سعة إنتاجية نهائية.
