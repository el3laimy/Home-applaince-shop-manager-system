# الدفعة 44: إصلاح إنشاء اختصار Windows

## العطل المثبت

في GitHub Actions run `34702270415` نجح بناء Windows وNSIS وفحص ملف المُثبّت وتشغيل التطبيق المثبت، ثم أبلغ اختبار القبول:

`Installer did not create required path: C:\Users\runneradmin\Desktop\إخلاص POS.lnk`

كان ملف NSIS محفوظًا بصيغة UTF-8 بلا BOM، بينما لم يحدد استدعاء `makensis` ترميز الإدخال. وفق دليل NSIS، الملفات بلا BOM تُقرأ بصفحة الرموز الافتراضية ما لم يمرر `/INPUTCHARSET`؛ لذلك لم يطابق اسم الاختصار الناتج النص العربي المتوقع. أكد run `34704284578` أن إنشاء مجلد Desktop وحده لا يحل العطل.

## الإصلاح

- ثُبت `SetShellVarContext current` صراحة لمساري التثبيت والإزالة.
- ينشئ المُثبّت `$DESKTOP` قبل `CreateShortcut`.
- يمرر سكربت البناء `/INPUTCHARSET UTF8` قبل ملف `.nsi`.
- إذا غاب مسار مطلوب، يعرض اختبار القبول أسماء العناصر الموجودة في المجلد الأب لتسهيل التشخيص دون إخفاء شرط الاختصار.
- بقي اختبار القبول يطلب الاختصار نفسه، حتى لا يتحول الإصلاح إلى تخفيف للشرط.

## القبول

اجتاز GitHub Actions run `34704965999` الوظائف الثلاث:

- Analyze and test: نجاح.
- Build Linux release ودورة Debian: نجاح.
- Build Windows release ودورة التثبيت والترقية والإزالة وإعادة التثبيت وبقاء بيانات المستخدم: نجاح.

بهذا تُغلق بوابة مُثبّت Windows الآلية في التقرير. تبقى تجربة جهاز Windows فعلي ممثل لجهاز المستخدم، وفحص SmartScreen بعد اعتماد هوية الناشر والتوقيع، قبل إعلان قبول ميداني.
