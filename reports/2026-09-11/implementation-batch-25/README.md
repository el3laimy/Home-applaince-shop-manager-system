# الدفعة 25: إغلاق منافذ تكرار الحركات المالية وترحيل آمن محليًا

التاريخ: 11 سبتمبر 2026.

## منع التكرار

- كل نقطة استخدام عامة تحرك مالًا في V2 ترفض التنفيذ قبل أي كتابة إذا غاب `operationKey`: البيع والشراء والمرتجع والمصروف، تحصيل قسط العميل، سداد قسط المورد، وفتح/إغلاق الوردية.
- نفس المفتاح مع نفس الحمولة يعيد نتيجة العملية المحفوظة دون قيد أو رصيد أو مخزون إضافي. إعادة المفتاح بحمولة مختلفة ترفض.
- بصمة البيع تضم ملاحظة وسيلة الدفع، مع إبقاء قراءة بصمة الإيصالات القديمة متوافقة.
- المخزون الافتتاحي أصبح عملية مالية محمية أيضًا: إضافة صنف برصيد افتتاحي تتطلب مفتاحًا وتحفظ إيصال `opening_stock` في نفس المعاملة. إضافة صنف برصيد صفر تظل عملية بيانات أساسية ولا تتطلب مفتاحًا ماليًا.
- طلب المخزون الافتتاحي يدخل مسار الطلب المالي المعلق، فيمكن التحقق من نفس الطلب بعد فقد الرد أو إعادة فتح التطبيق.
- أضيفت حواجز فورية في الواجهة لمنع النقرة السريعة الثانية في المصروفات ونافذة استعادة الطلب المالي قبل إعادة الرسم.

## اختبارات القبول المحلية

- `financial_operation_key_required_test.dart`: يغطي رفض المفتاح المفقود في كل العمليات العامة وعدم حدوث كتابة.
- `opening_stock_idempotency_test.dart`: يغطي الطلب المتزامن، وإعادة فتح قاعدة ملفية، وتعارض الحمولة، وفقد الرد، وفشل حفظ الإيصال مع رجوع المنتج والمخزون والقيد.
- `ui_submission_guards_test.dart`: يغطي النقر السريع المتكرر في المصروف والاستعادة.
- دخلت الاختبارات السابقة لمنع تكرار البيع والشراء والتحصيل والسداد والمرتجعات والمصروفات والورديات ضمن التحقق الشامل النهائي: **143 اختبارًا ناجحًا**.

## سلامة ترحيل قاعدة البيانات

- قبل ترحيل قاعدة أقدم تُفحص `quick_check` والنسخة، ثم تنشأ لقطة SQLite محققة وبصمة SHA-256 وعلامة حالة دائمة.
- قاعدة من إصدار أحدث تُرفض برسالة عربية قبل تغييرها.
- إذا انقطع ترحيل بدأ بالفعل، تعيد البداية التالية اللقطة المحققة وتحجب إعادة محاولة نفس البناء تلقائيًا. يستطيع إصدار التطبيق القديم فتح القاعدة المستعادة.
- اختبرت ترقية V4 إلى V5 ورفض V6 والفشل المتعمد ثم الرجوع. هذه اختبارات قاعدة صغيرة محلية، ولا تثبت قاعدة بحجم إنتاج أو انقطاع كهرباء فعليًا أو ترقية عبر المُثبّت.

## المتبقي لهذا القبول

- تجربة قتل العملية وقطع الكهرباء على نسخة بيانات كبيرة، ثم تشغيل فحص الاتساق.
- تجربة ترقية فعلية عبر مثبت Windows وحزمة Linux مع الاحتفاظ بالبيانات.
- سياسة تنظيف لقطات ما قبل الترقية بعد مدة معلنة، وتجربة امتلاء القرص وتعطل وسيط التخزين.
