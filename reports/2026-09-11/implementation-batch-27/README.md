# الدفعة 27: مسودات فواتير قابلة للاستعادة

التاريخ: 11 سبتمبر 2026.

## المنفذ

- مسودة مستقلة للبيع وأخرى للشراء تحفظ القيم الدقيقة وتعود بعد إعادة فتح قاعدة ملفية أو إعادة إنشاء نطاق التطبيق.
- تحذير عربي قبل ترك فاتورة معدلة وغير محفوظة عند التنقل أو تسجيل الخروج أو إغلاق نافذة سطح المكتب.
- حفظ المسودة لا ينشئ فاتورة أو قيدًا أو حركة مخزون، وحذفها صريح من الواجهة.
- تحويل ذري من المسودة إلى الطلب المعلق قبل التنفيذ؛ لا يمكن وجود الحالتين معًا للعملية نفسها.
- الطلب المعلق الذي لم يُحفظ ماليًا يعود إلى مسودة قابلة للتعديل. وجود إيصال عملية يمنع الرجوع كي لا تتكرر فاتورة محفوظة بعد فقد الرد.
- المسودة التالفة لا تحجب شاشة البيع أو الشراء ويمكن مسحها برسالة واضحة.
- لم يتغير مخطط SQLite؛ التخزين يستخدم إعدادات التطبيق ذات الصيغة `v1` مع تحقق صارم من الحمولة وحد أقصى للبنود.

## التحقق

- `dart analyze lib/v2 lib/main.dart test/v2`: لا توجد مشاكل.
- `flutter test --no-pub test/v2`: **150 اختبارًا ناجحًا**.
- اختبارات الواجهة تشمل الحد الأدنى للنافذة 1024x720، الأرقام العربية، إعادة التشغيل، حفظ القيم الدقيقة، التسجيل مرة واحدة، وفساد المسودة.
- `git diff --check`: ناجح.
- `flutter build linux --release --no-pub`: ناجح.
- بُنيت حزمة Debian وفُحص ملف التحكم والمحتويات.

## حدود القبول

المسودة تحفظ عند ضغط الزر ولا تعمل تلقائيًا مع كل تعديل؛ قد تضيع تعديلات الذاكرة عند قتل العملية أو انقطاع الطاقة قبل الحفظ. اختبار Widget يغطي طلب إغلاق النافذة منطقيًا، لكنه لا يثبت حدث الإغلاق الأصلي على Windows أو Linux. يلزم اختبار الجهاز الفعلي قبل اعتماد الإصدار للمستخدم النهائي.
